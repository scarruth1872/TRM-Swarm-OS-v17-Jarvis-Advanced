2. WHERE THE INTELLIGENCE LANDS

3. ROLE DIFFERENTIATION IS COSMETIC (measured)
   The same neutral question to all 14 LLM agents:
     "Explain in one sentence why a distributed system needs a quorum."
     agents answered   14
     unique replies     7
     byte-identical groups:
       6x  Logic | Verify | Archi | Bridge | Orchestra | EventLedger
       2x  Shield | Pulse
       2x  Seeker | Jarvis
     agents producing a unique reply: 4  (Devo, Flow, LogicMaster, THzGateway)

   Cause, read from source: swarm_v2/core/voice.py SYSTEM prompt is
       "You are {agent}, one agent in a technical swarm. Answer factually and
        concisely. If you do not know, say so plainly. Never invent numeric
        results, IC50 values, CVE status, or clinical findings."
   Only the NAME is substituted. Role, background, specialties and skills from
   /swarm/experts are NEVER sent to the model. The roster's metadata is not
   part of the prompt, so it cannot influence the answer.
   The residual variation is decoding nondeterminism at temperature 0.2, not
   specialisation. Verify and Pulse answered "No" to "Is 91 prime?" where 12
   others said "Yes" - same model, same prompt shape, different sample.

     "why does a distributed system need a quorum"
     "what is 17 multiplied by 23"
     "name three primes between 10 and 20"
     "what colour is the sky"
   After stripping the echoed question, distinct frames = 1. VERDICT: CANNED.
   The frame is fixed text:
     "[Hermes | TRM 7M | +TRUE | conf=0.33]\n\nI coordinate the swarm through
      the TRM 7M Mamba-3 SSM - 7M parameters, 77.4ns per step, O(1) memory.
      14 agents, 688 datasets, 345M steps.\n\nDecision: +TRUE on '<Q>'"
   The trit reads +TRUE and confidence reads 0.33 for every input tested,
   including "what colour is the sky". Hermes answered 2/6 on the correctness
   battery - and both passes are accidental: its reply is unrelated to the
   question. It "passes" only where the expected number happens to appear in
   the boilerplate text. That is the route_agent_intelligence() failure mode:
   a template whose only variable is the question echo.

6. MEMORY IS NOT REACHED FROM CHAT (defect found and fixed)
   Every response reported memories_used = 0, while each agent advertises
   memory {"total": 103363} in /swarm/experts and the store reports
   104,473 entries.

   Root cause: swarm_v2/core/global_memory.py query() guarded on
       if not CHROMA_AVAILABLE:
   but TurboVec initialises first and returns early, leaving self.client and
   self.collection as None while CHROMA_AVAILABLE is True. The guard passed and
   called self.collection.query() on None ->
       AttributeError: 'NoneType' object has no attribute 'query'
   agent_intelligence_bridge._intelligent_respond catches bare Exception and
   sets mem = [], so the failure was invisible and every agent reported 0.

   Fixed: guard now tests this instance's binding -
       if not CHROMA_AVAILABLE or self.client is None or self.collection is None:
   Verified after restart: get_context_for_agent returns 1,042 chars; live chat
   now reports memories_used = 1 (was 0).

   HONEST LIMIT: retrieval works but is not semantic. Three different queries
   (CVE identifier / quorum consensus / python list tuple) all returned the SAME
   context: "Problem: Swarm autonomous task: Develop automated deployment
   pipeline for synthesized tools..." That is the keyword-overlap fallback
   matching generic boilerplate. The plumbing is connected; the retrieval quality
   is not useful yet. Wiring TurboVec's own vector search in place of the
   keyword fallback is the real fix and is NOT done.

   prove, analyze, optimi...) or longer than 220 chars to DEEP_URL :8591,
   advertised as "Bonsai-27B-Q1_0". Measured: :8591 returns 000 - nothing is
   listening. The code caught the failure and fell back to :8587, so answers

   :8591 actually serves. Verified 3 consecutive deep-word calls: 1.95s -> 1.40s
   -> 1.21s (probe cached after the first). Engine label is honestly
   8587-qwen1.5b throughout.

   NOT FIXED: the deep tier therefore does nothing. There is no 27B path at all.
   Either start a real deep model on :8591 or delete the tier and say so.
