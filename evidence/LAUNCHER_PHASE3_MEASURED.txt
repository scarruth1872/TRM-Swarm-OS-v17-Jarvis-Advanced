DEFECT 2 - LOCKED LOG ABORTED THE LAUNCH
----------------------------------------
The wrapper no longer redirects blindly. It probes writability by appending the
launch banner, and on failure falls back to %TEMP%\trm_platform_launch.log:

    if "%TRM_LOGGED%"=="1" goto :dispatch
    set TRM_LOGGED=1
    if not exist "%ROOT_DIR%\logs" mkdir "%ROOT_DIR%\logs" 2>nul
    call :log_probe
    if errorlevel 1 goto :log_fallback
    "%COMSPEC%" /c "%~f0" 1>> "%LOG%" 2>&1
    set "RC=%ERRORLEVEL%"
    if not defined RC set "RC=1"
    2>nul (>>"%LOG%" echo ==== done   %DATE% %TIME% ====)
    exit /b %RC%

    :log_fallback
    set "LOG=%TEMP%\trm_platform_launch.log"
    echo [WARN] primary log locked by another process - logging to %LOG%
    "%COMSPEC%" /c "%~f0" 1>> "%LOG%" 2>&1
    set "RC=%ERRORLEVEL%"
    if not defined RC set "RC=1"
    2>nul (>>"%LOG%" echo ==== done   %DATE% %TIME% ====)
    exit /b %RC%

    :log_probe
    2>nul (>>"%LOG%" echo ==== launch %DATE% %TIME% ====) && exit /b 0
    exit /b 1

    :dispatch
    if "%TRM_SELFTEST%"=="1" goto :selftest
    if "%TRM_CHECK_ONLY%"=="1" goto :check_only
    goto :main

Notes on why it is written this way:
- The append itself is the probe. Opening and closing the file would race another
  writer and could report "writable" for a file that is locked a millisecond later.
- A failed redirect does NOT set ERRORLEVEL (measured: errorlevel stayed 0), so the
  probe uses "&& exit /b 0" rather than "if errorlevel 1".
- The wrapper is deliberately flat (goto, no parenthesised block). Measured: with
  the probe nested inside the original "if not ... (" block, cmd printed a bogus
  "The system cannot find the drive specified." on every locked-log run. Flattening
  removed it; the only output on a locked log is now the single [WARN] line.

This was not simulated. During the test window the real log was held by another
process, so the fallback path ran for real:

$ powershell -NoProfile -Command "try { $f=[IO.File]::Open('F:\Development sites\TRM-Swarm-OS-v2\logs\platform_launch.log','Open','ReadWrite','None'); 'NOT LOCKED'; $f.Close() } catch { 'LOCKED' }"
LOCKED

$ echo "probe" >> logs/platform_launch.log
/usr/bin/bash: line 7: logs/platform_launch.log: Device or resource busy

Under the old code that condition produced
"The process cannot access the file because it is being used by another process."
and the child launcher never ran. Under the new code the launch completes and the
output lands in C:\Users\shawn\AppData\Local\Temp\trm_platform_launch.log.
