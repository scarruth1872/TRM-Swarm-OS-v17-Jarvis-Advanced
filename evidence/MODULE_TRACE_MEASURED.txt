6. INSTRUMENT ERRATA (my bugs, kept not deleted)
================================================
The first committed trace reported three wrong Rust figures. All three were
bugs in tools/trace_codebase.py, not facts about the code:
  1. crate roots normalised to 'crate_root' but file keys did not, so every
     main.rs-rooted crate showed 0 reachable: host_tranche 0/28 (actual 2/28),
     host_fanout 0/15 (actual 5/15), openfang-cli 0/36 (actual 34/36).
  2. crates with BOTH lib.rs and main.rs collided on one key, so one file's LOC
     and test count overwrote the other's: LOC fell 240,167 -> 239,649 while the
     file count stayed 661. Fixed with a @filename collision suffix.
  3. a syntax-error record omitted stub_markers and crashed the summary.
A measurement tool is code; its first output must be checked against a case whose
answer is already known. The pre-fix trace was self-consistent and wrong.
