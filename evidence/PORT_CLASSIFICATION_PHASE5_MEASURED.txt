Why it was wrong: cargo metadata --no-deps reports two targets for this package:
  trm_uefi_kernel [lib]  src\lib.rs
  trm_uefi_kernel [bin]  src\main.rs
A crate root is declared by Cargo, not by a `mod X;` line, so the orphan scan
(which looks for `mod` declarations) can never see it. `main` was hardcoded as an
exception; `lib` was not.

THE FIX (tools/surface_diff.py — one function added, one line changed):

  + def crate_roots():
  +     """Stems of this crate's ROOT files, which are never modules. ..."""
  +     roots = {"main", "lib"}        # Cargo defaults: src/main.rs, src/lib.rs
  +     manifest = RSDIR.parent / "Cargo.toml"
  +     try:
  +         import tomllib
  +         data = tomllib.loads(manifest.read_text(encoding="utf-8"))
  +     except Exception:
  +         return roots
  +     for key in ("lib", "bin"):
  +         targets = data.get(key)
  +         if isinstance(targets, dict):
  +             targets = [targets]
  +         for target in targets or []:
  +             path = target.get("path") if isinstance(target, dict) else None
  +             if path:
  +                 roots.add(pathlib.Path(path).stem)
  +             else:
  +                 roots.add("main" if key == "bin" else "lib")
  +     return roots

  - files.discard("main")          # crate root, correctly not a module
  + files -= crate_roots()         # crate roots are targets, not modules

No other logic in the tool was touched. The classification, shape, and surface
comparison code is byte-identical.
