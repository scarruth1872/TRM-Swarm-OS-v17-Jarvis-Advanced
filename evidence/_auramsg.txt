AUDIT - WHAT phi_v ACTUALLY MEASURES
  POSITIVE: it is genuinely derived, not constant. 3 distinct values over 30s
  (0.5755 / 0.577 / 0.5773) tracking memory_percent 84.89 -> 84.54; and 0.5771 ->
  0.5751 across the session. My first 8-call test showed 1 distinct value and I
  nearly reported a doctrine violation - the window was simply too short, since
  memory usage is the only live input and it moves over minutes.

  FINDING: it carries no voltage measurement. In voltage.rs,
      const V_CORE = 1.25   and the formula divides by 1.25
      const V_DDR  = 1.35   and the formula divides by 1.35
      const F_BASE = 4000   and the clock reads 4000
  so phi_core = (1.25/1.25)^2 = 1.0, phi_mem = 1.35/1.35 = 1.0 and
  phi_freq = 4000/4000 = 1.0 - each IDENTICALLY. phi_v reduces to 1 - mem%/200.
  Verified: mem 84.72 -> computed 0.576400, reported 0.5764.
  A constant equal to its own divisor can never be anything but 1.0, so the rail
  terms are structurally inert. The endpoint names its inputs honestly ('wmic
  CurrentClockSpeed + OS memory' - no rail read is claimed), but the field is
  named voltage_phi_v and voltage_rails is served as {v_core: 1.25, v_ddr: 1.35},
  which reads as measurement rather than nominal constants.
  TO FULLY SATISFY THE DOCTRINE: read the rails instead of declaring them.
