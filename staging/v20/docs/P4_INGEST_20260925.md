# P4 — `relational/` + the structured stores, ingested (2026-09-25)

**Acceptance (from `FULL_PLAN_ARTIFACTS_AND_SETUP_20260924.md`):** "one text document per record, each
carrying `source file` + archive sha256, through the existing encoder; a stated, bounded sample with the
fraction recorded; chemistry queries go to the structured index, not the fabric."

**Result: all three clauses met, and the third one required repairing the index first** — the structured
store held 2,897,819 identifiers and not one structure, so "chemistry queries go to the index" led
nowhere until it was fixed.

## 1. The relational records, as documents, through the existing encoder

`scratch/p4_extract_records.py` (in WSL, where the corpus is) → `scratch/p4_ingest_relational.py` (the
sovereign `NativeEmbeddingSkill`, 768-dim, no external model). Each document carries its own provenance:

```
source: enwikiquote.xml.bz2#41200
archive_sha256: <sha256 of the 214 MB archive>
record_kind: wiki  record_index: 41200
title: … / <text>
```

| source | sampled | available | fraction |
|---|---|---|---|
| ethics_commonsense.csv | 200 | 13,910 | 1.44% |
| ethics_deontology.csv | 200 | 18,164 | 1.10% |
| ethics_justice.csv | 200 | 21,791 | 0.92% |
| ethics_utilitarianism.csv | 200 | 13,737 | 1.46% |
| ethics_virtue.csv | 200 | 28,245 | 0.71% |
| gutenberg / lawofone / 5× wisdom (chunks) | 294 | 6,151 | 4.78% |
| enwikiquote.xml.bz2 (articles) | 700 | 81,695 | 0.86% |
| ed_train.csv | 0 | 0 | — |
| **total** | **1,994** | **183,693** | **1.09%** |

The denominators are **counted, not assumed** — enwikiquote is fully streamed to count its 81,695
articles (namespaces filtered out), and the sample is a deterministic every-k-th stride, so it
reproduces. `ed_train.csv` is a 14-byte truncated download: counted, and refused as a corpus.

**Measured: 1,126.8 docs/s, not the ~169 docs/s the ingestion design assumed** — the design's own
arithmetic over-estimated the cost of any given sample by ~6.7×. Index: 186 → **2,180 documents,
53.2 MB**.

**Reachable, proved through the compiled runtime:** the kernel caches the index in a `OnceLock`, so a
fresh ingest is invisible until it restarts. Restarted (pid 14124 → 28076, `/health` **4.9 s** — the
53 MB startup parse), then `GET /k3/retrieve?q=Charles De Gaulle&k=3` → **rank 1 =
`relational/enwikiquote.xml.bz2#100`**, fidelity 0.8948, served by the Rust kernel.

## 2. The structured store: identifiers → structures

The defect: `molecule` held **2,897,819 rows, all with `smiles` NULL and `props = 'chembl_id'`** — a
"fully ingested" ChEMBL release that stored only the ID column, so no chemistry question could be asked
of it. The SDF is gzip on the WSL side (931 MB compressed; the design doc says 701 MB) and RDKit is
installed on this side only, so the decompressed stream is piped into RDKit:

`wsl.exe -e bash -lc 'zcat ~/drugs/chembl_37.sdf.gz' | py -3 scratch/p4_chembl_smiles_stream.py --limit 200000`

**199,997 structures from 200,000 records (3 unparsable) at 1,288 rec/s**, each with canonical SMILES +
MW + Crippen logP + HBD/HBA + heavy atoms. Written into the existing `molecule` rows (no parallel
store): **`smiles` 0 → 199,997 of 2,897,819 = 6.90%**, 199,997 rows updated in 2.26 s. The store was
copied to `backups/p4_structured_index_pre/structured_index.db` (507,248,640 B, verified: smiles = 0)
before the write; it is now 532,578,304 B.

**The fork, demonstrated rather than asserted.** A property filter no fabric retrieval can answer:

```sql
select chembl_id, smiles from molecule
where smiles is not null and json_extract(props,'$.mw') between 300 and 350
  and json_extract(props,'$.logp') between 1 and 3 and json_extract(props,'$.hbd') <= 3
```
→ **9,937 matches** (e.g. `CHEMBL42426`, mw 300.068, logp 2.02).

**Not available, and stated:** substructure search. This store has column filters and no fingerprint
index; claiming otherwise would need a Morgan/ECFP build that does not exist yet.

## 3. Defects found on the way

1. **`molecule` stored identifiers only** — the headline one; fixed for 6.90% of rows.
2. **My own denominator was wrong** for `ethics_commonsense.csv`: I counted lines (54,093) where the
   file has quoted multi-line fields. The `csv` module gives 13,910 — matching the platform's own
   earlier ingest, which is what caught it. Fixed, and the ingest now replaces rather than accumulates,
   so no stale documents survived the correction.
3. **The design doc's SDF size (701 MB) is stale** — the file is 931,156,420 B.
4. `ed_train.csv` is a 14-byte stub, not a corpus.

## Not claimed

Not that the fabric "knows" the relational corpora (1.09% of it is present, with the design's own
warning about short-query discrimination intact), and not that ChEMBL is filled in (6.90% of rows). What
is claimed is narrow: the sample exists as documents with provenance, they are retrievable through the
kernel's own route, the store answers property queries, and every fraction above is measured.
