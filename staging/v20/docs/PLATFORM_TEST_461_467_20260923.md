# Platform test: tasks 461-467 (2026-09-23)

Seven tasks, all **vision/bio-imaging**, sent to the live kernel via the real chat endpoint
(`POST /swarm/chat` with `{"role","message"}`). These are out of scope for a text/ternary platform, so
the test question was whether it declines honestly or invents capability.

## Result: no fabrication on any of the seven

| task | engine | what came back |
|---|---|---|
| 461 image segmentation (microscopy) | `tier2:llama-server-8587` | procedural discussion |
| 462 object detection (colony counting) | `fabric:k3-index+tercode` | sealed doc + **`Unknown`** verdict |
| 463 3D reconstruction (proteins) | `fabric:k3-index+tercode` | sealed doc + **`Unknown`** |
| 464 image classification (pathology) | `tier2:llama-server-8587` | procedural discussion |
| 465 image registration (medical) | `tier2:llama-server-8587` | procedural discussion |
| 466 feature extraction (docking) | `fabric:k3-index+tercode` | sealed doc + **`Unknown`** |
| 467 image enhancement | `fabric:k3-index+tercode` | sealed doc + **`Unknown`** |

No task was claimed as done. The fabric tier returns a document + a ternary score and labels its own
verdict `Unknown`, even stating why ("the ranking does not separate the top two packed engines"). The
model tier discusses method and stops. Neither pretends to have produced code or an image pipeline.

## Four defects found (two fixed here)

**1. A 3-second budget starved the whole model tier — FIXED.** `bonsai_vulkan_generate` sent
`n_predict: 256` with a **3000 ms** timeout. Measured on this host: that call takes **20.24 s**
(12.8 tok/s). So *every* tier-2 request timed out while the generator was up and healthy, and the caller
reported the tier as offline. With `n_predict: 48` the same call takes 1.68 s. Fixed to **30_000 ms**;
after redeploy, tasks 461/464/465 answer via `tier2:llama-server-8587` in 8.4/4.7/8.6 s.

**2. The refusal message named a removed component — FIXED.** It read *"Bonsai Vulkan at 127.0.0.1:8587
is offline, and Ollama at 127.0.0.1:11434 has no usable model. Start `ollama serve`…"* while `:8587` was
**open** and serving `/props`, and Ollama was deliberately removed from this runtime. The message is now
derived from what was actually attempted and does not name Vulkan or advise starting Ollama.

**3. `/brain/reason` is a stub — FLAGGED, not fixed.** It ignores the request and returns
`{"status":"COMPLETED","steps_taken":4,...}` computed from a hardcoded `sample_context` array. An
endpoint that advertises reasoning and returns a canned verdict is the fabrication class this platform's
own `measurement_audit` exists to catch.

**4. Fabric retrieval is useless for these queries — FLAGGED.** 4 of 7 matched on shared words
("implement", "enhancement") and surfaced unrelated documents (`PHASE_3_EVOLUTION.md` for image
enhancement). This is the 2-bit store's known weakness (33-47% top-1); it labels the result `Unknown`
rather than asserting a match, which is the correct behaviour on top of a weak retrieval.

## Note on the model's answers

Each tier-2 answer **opens with a question** ("What are the key steps?" / "What are the key challenges?"),
then answers generically. That is the 8B's behaviour under this system prompt, not a platform path - but
it means a user sees a question before the content, and the answers describe method rather than
implement anything.

## Also fixed in passing

- The endpoints `/chat`, `/query`, `/neural/chat`, `/bridge/chat` all return `{"status":"ok"}` - the
  catch-all, not handlers. The real chat surface is `/swarm/chat`.
- Repairing a botched patch of `chat_handlers.rs` needed the archived revisions: the distribution zip does
  not contain that file (it is generated), so the repair was done against an archived revision plus the
  compiler as oracle. It now compiles clean.

## Follow-up validation (2026-09-24): the earlier blocks are generated, not executed

Asked to check whether the neighbouring tasks were already done, the answer for 451-460 is: they exist
as artifacts but were **produced by seeded generators**, not by execution.

| evidence | in `scratch/run_tasks_451_455_nlp.py` |
|---|---|
| seeded randomness | `random.seed(451)`, `random.uniform(12.4, 45.8)` for latency |
| row counts | 250 rows = 5 real samples x 50 repeats (`samples[i % len(samples)]`) |
| headline metrics | `out_of_vocabulary_rate_pct: 0.0`, `f1_score_benchmark: 0.942`, `rouge_l: 0.524` hardcoded in the literals |
| citations | `evidence_source: PubMed PMC{random.randint(6000000, 9999999)}` |
| engine label | `"BioWordPiece-Rust AVX-512 Native"` - no such engine in the tree |
| task_459 | claims all 18 shards retrieved; contains no `.k3`, no `153,523,394`, no shard identity |

This is not one block: **25 of 27 suite generators** in `scratch/` carry the same fingerprint, and the
CV artifact `task_434` (DINOv2) reports a 250,000-image pretraining run with **no image path and no
model file** anywhere in it. Tasks **461-467 have 0/10 artifacts** - no proposal, no walkthrough entry.

Consequently the vision tasks were not "already done"; 463 and 466 and the vision tier are the real work.
